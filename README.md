# Определение года события по упоминанию сановников — ЛР3 (веб-сервис)

`Услуги` — `dignitarie_lists`: сановники (визири, консулы, воеводы) с датами пребывания в должности.
Поля по теме: `start_date` — дата вступления в должность и `end_date` — дата оставления должности.

Веб-сервис на Go (Gin + GORM), данные в PostgreSQL, изображения и видео — в MinIO.
До ЛР4 текущий пользователь зафиксирован константой (id = 1) в функции-singleton `CurrentUser()` (`internal/app/handler/current_user.go`).

## HTTP-методы (10)

Все адреса начинаются с `/api`. Ответы — JSON, ошибки — `{"status": "error", "description": "..."}`.
Системные поля (id, статус, создатель, даты создания и формирования) клиент передать не может — они вычисляются на сервере. В ответах только поля, нужные странице.

### Домен «услуги» (`/api/dignitarie_lists`)

| № | Метод  | URL                                                    | Параметры / тело запроса                                                          | Ответ                                                                                                  |
|---|--------|--------------------------------------------------------|------------------------------------------------------------------------------------|--------------------------------------------------------------------------------------------------------|
| 1 | GET    | `/api/dignitarie_lists`                                | необязательный `date` — календарная дата ГГГГ-ММ-ДД (в должности в эту дату)       | 200: массив опубликованных услуг. Поля: `id`, `name`, `image_url`, `start_date`, `end_date`, `likes_count`, `is_creator` (0/1 — создатель услуги совпадает с текущим пользователем) |
| 2 | GET    | `/api/dignitarie_lists/feed`                           | необязательные `id` и `next`: без `id` — первая услуга, `id` — по ID, `id`+`next=true` — следующая | 200: одна опубликованная услуга. Поля: `id`, `name`, `description`, `image_url`, `video_url`, `start_date`, `end_date`, `likes_count`, `is_liked` (0/1 — текущий пользователь лайкнул), `is_creator` (0/1); 404 — не найдена |
| 3 | GET    | `/api/dignitarie_lists/draft`                          | — (id не указывается)                                                              | 200: черновик текущего пользователя (не более одного). Поля: `id`, `name`, `description`, `image_url`, `video_url`, `start_date`, `end_date`, `status`; 404 — черновика нет |
| 4 | POST   | `/api/dignitarie_lists`                                | `multipart/form-data`: `name`, файлы `image` (image/*, до 10 МБ), `video` (video/*, до 50 МБ) | 201: созданный черновик (поля как в п. 3). Файлы сохраняются в MinIO под сгенерированными латинскими именами, в БД — их url; 409 — черновик уже есть |
| 5 | PUT    | `/api/dignitarie_lists/draft/publish`                  | JSON: `description`, `start_date`, `end_date` (ГГГГ-ММ-ДД)                         | 200: опубликованная услуга (статус «опубликован», заполнена дата формирования); 404 — черновика нет    |
| 6 | DELETE | `/api/dignitarie_lists/:id`                            | —                                                                                  | 200: логическое удаление (статус «удален»), только услуги текущего пользователя; 403 — чужая услуга; 404 |
| 7 | POST   | `/api/dignitarie_lists/:id/like`                       | JSON: `liked` — 1 поставить лайк, 0 отменить                                       | 200: `dignitarie_list_id`, `is_liked`, `likes_count`                                                  |

Статус меняется только вперёд: создание даёт «черновик», публикация — «опубликован», удаление — «удален». Вернуть в черновик нельзя.

Лента работает и без параметров, потому что при переходе с панели вкладок идентификатор не указывается: возвращается первая опубликованная услуга. Метод «Далее» — тот же метод ленты с параметрами `id` и `next=true`, отдельного адреса у него нет.

## Таблицы БД

### `users` — пользователи

| Поле            | Тип          | Ограничения                  | Описание                           |
|-----------------|--------------|------------------------------|------------------------------------|
| `id`            | bigint       | PK                           | идентификатор                      |
| `login`         | varchar(50)  | NOT NULL, UNIQUE             | логин                              |
| `password_hash` | varchar(60)  | NOT NULL                     | bcrypt-хеш пароля                  |

### `dignitarie_lists` — услуги

| Поле           | Тип                | Ограничения                                         | Описание                                        |
|----------------|--------------------|-----------------------------------------------------|-------------------------------------------------|
| `id`           | bigint             | PK                                                  | идентификатор                                   |
| `name`         | varchar(255)       | NOT NULL                                            | наименование                                    |
| `description`  | text               | необязательное                                      | краткое описание                                |
| `status`       | varchar(20)        | NOT NULL                                            | черновик / опубликован / удален                 |
| `image_url`    | varchar(500)       | NOT NULL                                            | url изображения в MinIO                         |
| `video_url`    | varchar(500)       | NOT NULL                                            | url видео в MinIO                               |
| `start_date`   | date               | необязательное                                      | поле по теме: дата вступления в должность       |
| `end_date`     | date               | необязательное                                      | поле по теме: дата оставления должности         |
| `created_at`   | timestamptz        | NOT NULL                                            | дата создания                                   |
| `published_at` | timestamptz        | необязательное                                      | дата формирования (публикации)                  |
| `creator_id`   | bigint             | NOT NULL, FK → users(id), ON DELETE RESTRICT        | создатель                                       |

Один черновик на пользователя — частичный уникальный индекс `idx_one_draft_per_creator` (`status`, `creator_id`) при `status = 'черновик'`. Дата окончания не раньше даты начала — проверочное ограничение.

### `dignitarie_list_likes` — лайки (связь многие-ко-многим пользователь–услуга)

| Поле                | Тип    | Ограничения                                          | Описание       |
|---------------------|--------|------------------------------------------------------|----------------|
| `id`                | bigint | PK                                                   | идентификатор  |
| `user_id`           | bigint | NOT NULL, FK → users(id), ON DELETE RESTRICT         | кто поставил   |
| `dignitarie_list_id`| bigint | NOT NULL, FK → dignitarie_lists(id), ON DELETE RESTRICT | какой услуге |

Пара (`user_id`, `dignitarie_list_id`) уникальна. Каскадного удаления нет.

## Запуск

1. `cp .env.example .env` (Postgres снаружи на порту 5433)
2. Поднять Postgres, Adminer и MinIO:
   ```bash
   docker compose up -d
   ```
3. Создать таблицы:
   ```bash
   go run ./cmd/migrate
   ```
4. Заполнить данными: Adminer http://localhost:8081 (PostgreSQL, сервер `db`, пользователь/пароль/БД из `.env`) → «SQL-запрос» → содержимое `seed.sql`. Пароль всех тестовых пользователей — `password123`.
5. Запустить веб-сервис:
   ```bash
   go run ./cmd/dignitarie_lists
   ```
   API: http://localhost:8080/api/dignitarie_lists
